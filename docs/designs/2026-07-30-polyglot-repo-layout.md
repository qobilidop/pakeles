# Polyglot repo layout: by artifact, not by language

**Decision (2026-07-30).** The repo root holds only language-neutral
trees (`proto/`, `examples/`, `testdata/`, `docs/`, `third_party/`)
beside the two language surfaces `rust/` and `python/`. Within that,
the organizing principle is **artifact-first**: a thing lives with the
thing it is about, not with the language it happens to be written in.

## What that means concretely

- `rust/` holds the four **toolchain** crates (core, cli, testkit,
  pbgen) — not "all Rust code". The five real-world example crates
  live under `examples/real_world/<x>/` beside their descriptions,
  goldens, and factories, because "everything about one incumbent in
  one directory" is what makes an agreement claim reviewable. A
  `rust/` that promised to contain all Rust code would be false the
  day it was created.
- `python/` is one artifact (the authoring eDSL) whose identity *is*
  its language, so the language is its best name. Project root
  directly inside (`python/pyproject.toml`, src layout) — no
  `python/pakeles/` nesting for a single package.
- `third_party/` is the entire licensing story: code not written for
  this repo lives (or, for katran's fetch-only GPL sources, lands)
  there and nowhere else.

## The enabler: vendor-and-guard generated code

What used to weld the core crate to the repo root was build-time
protobuf generation: `cargo package` cannot include `../proto`, so the
crate had to sit where `proto/` was inside its package boundary. Both
language surfaces now vendor their generated code — `python/` its
`_pb` modules (as it always did), `rust/pakeles` its prost/pbjson
output (`src/gen/`, regenerated by `pakeles-pbgen`) and its embedded
synthetic-gallery IRs (`src/examples/`, refreshed by `gen_examples`) —
each equality-guarded against the canonical source by a test. Costs
and gains:

- **Gain:** the packaged crate is self-contained; consumers never need
  protoc (prost-build requires a system protoc since 0.11, so this
  mattered for publication independently of layout).
- **Cost:** a manual regen step after every `proto/` change
  (`./dev.sh cargo run --bin pakeles-pbgen`); the guard test turns a
  forgotten regen into a red gate, not silent drift.

## Rejected alternatives

- **Language-first split** (`rust/` = all Rust): breaks the
  directory-complete example crates; optimizes for the wrong reader.
- **`crates/` container with core still generating at build time**:
  impossible to package (the `../proto` problem) without moving the
  neutral schema inside one language's tree.
- **Symlinking proto into the crate**: cargo packaging handles
  symlinked directories poorly; not portable.

## Consequences for contributors

- A bare `cargo test` at the root runs every workspace member (virtual
  root — all members are default).
- The CLI is `cargo run --bin pakeles -- ...` from anywhere in the
  workspace.
- After editing `proto/`: run `pakeles-pbgen`, then the python protoc
  step (`python/README.md`), then `scripts/gen-examples.sh`.
